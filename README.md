# a11yguard2 · 无障碍守护

把 Android 无障碍服务「钉住」，服务被系统杀掉后自动拉回来；同时提供多种**不用看屏幕**就能切换无障碍服务的手势。

给读屏用户（TalkBack / TalkMan / 解说等）用的：读屏失灵时最常见的痛苦是「它突然不说话了」，而恢复它又需要看得见屏幕去系统设置里操作——正好形成死循环。这个应用就是为了打破这个循环。

## 它做什么

### 一、保活：让无障碍服务不轻易掉

Android 会定期清理后台的无障碍服务，尤其是在内存紧张、锁屏时间长、厂商省电策略激进时。掉线后用户听到的只是「突然没声音了」。

本应用用一个轻量的前台服务 + 无障碍服务互相看护：

- 检测到目标服务掉线后自动重新绑定
- 记录启动 / 重启 / 拉活次数，界面可见
- 修复失败时写诊断日志，便于排查是哪一环断了

> 实测数据（作者自己的 OPPO / Android 16 设备，长期运行）：
> 成功 16 · 失败 0 · 启动 35 · 重启 28 · 拉活 282

### 二、手势：不看屏幕也能切换服务

所有手势共用同一套「目标服务」选择器——选一个无障碍服务，手势触发时切换它。

| 手势 | 说明 | 熄屏可用 |
|------|------|---------|
| **音量键双击** | 上键 / 下键分别绑定不同目标 | ✅ |
| **摇一摇** | 甩动手机 N 次（可配 1–4） | ⚠️ 视机型 |
| **背面敲击** | 敲击手机背面 2–3 次 | ⚠️ 视机型 |

> **已移除**：距离感应挥手、抬腕。两者基于传感器二元值判断动作性质，
> 实测无法可靠区分「挥手」与「遮挡」、「抬腕」与「随手拿起其他东西」，
> 误触发率不可接受，故移除。

每个手势都有独立开关、独立目标、独立参数（次数、窗口、灵敏度、冷却）。

## 为什么这些手势可靠

这不是「随便听个传感器事件就触发」的粗糙实现。每个手势都有一段可以单元测试的纯逻辑（`*Logic.kt`），把物理动作和业务动作分开：

### 为什么没有摇一摇（如实记录）

摇一摇做过 6 个版本、4 种判据，**全部失败**，最终移除。记录在这里是为了让后来者不必重走：

| 判据 | 失败原因 | 实测证据 |
|------|---------|---------|
| 只看力度 |‖a‖-g| | 放下手机撞击桌面的峰值远超真实甩动 | 撞击 peak=32.8，甩动 peak=5.1 —— **提高阈值只会更难用，挡不住放下** |
| ‖a‖-g 符号翻转 | 真实甩动时手机始终被手推着加速，‖a‖ 一直在 g 以上，符号**永不为负** | 日志全是「0 次往复」，任何摇动都被拒 |
| 线性加速度点积 < 0 | 甩动是「爆发 → 匀速段≈0 → 反向爆发」，dot(爆发, 零) ≈ 0 **永不为负** | 摇 10 次只成功 1–2 次 |
| 爆发计数（上升沿） | 手机磕桌面会**弹跳**，一次撞击产生 3–7 次爆发 | 同类撞击有时被拒（1 次）有时误触发（4 次） |

**根本教训**：这些判据都是基于「自己构造的模拟数据」调出来的，而模拟数据不含真实世界的
弹跳、握持角度差异、个体甩动幅度差异。**应该先录真实数据再设计判据** —— 项目里因此
保留了一个传感器录制器（诊断页），供将来真要做时使用。

在真机上，「摇一摇」这类基于加速度的手势很难同时做到「随手一甩就响」和「拿起放下不误触」。
如果你需要不看屏幕的手势，**音量键双击**是最可靠的（硬件事件，不受姿态影响）。
### 音量键：超时后主动丢弃上一次按键

单击之后如果超过窗口期才按第二下，必须**放弃之前那次单击**、从 1 重计。

典型错误实现是 `if (now - last < win) count++ else count = 1`，但忘了在读 `count` 之前先做超时清零，于是 `count` 一直停在 1，**隔几分钟再按一次也会触发**。

代码见 `KeyPressLogic.kt`，测试见 `KeyPressTimeoutTest.kt`（含「正好等于窗口值判超时」「隔 5 分钟再按仍算第一下」等边界用例）。

## 一个必须知道的坑：目标服务的两种存储格式

设置页有两类「目标」：

- **锁屏 / 解锁动作** 写入带前缀的 `toggle:<component>`
- **音量键 / 各手势** 直接写入裸组件名 `<component>`

而执行端 `Triggers.runAction()` 早期只认 `none` / `master` / `toggle:` 三种。于是裸组件名三条分支全不匹配、**静默什么都不做**。

诊断特征非常有迷惑性：诊断日志里能看到 `[volkey] double DOWN → <component>`，说明手势**识别成功了**，但目标服务毫无反应、也没有任何 `want=...` 日志。

现在 `runAction()` 增加兜底分支：不含 `/` 之外的裸组件名（含 `/` 的）一律按 `toggle:` 处理，未知值写日志。回归测试见 `ActionParseTest.kt`。

**教训**：凡是「写入端有多种格式」的配置，执行端必须有对应的兜底 + 未知值告警，否则就是静默失效。

```bash
# 需要 JDK 17、Android SDK 35
# local.properties 里写自己的 sdk.dir
./gradlew assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

跑单元测试：

```bash
./gradlew testDebugUnitTest
```

## 使用

1. 安装后打开应用
2. 授权无障碍：进入「辅助功能」把本应用的两个服务都打开（`GuardA11yService` 保活 + `TapAgentService` 手势）
3. 在「手势」页给每个手势选一个目标服务
4. 打开对应手势的开关

> **重要**：「点按代理」（TapAgentService）不开，所有手势都不生效，因为传感器监听挂在它上面。

## 权限说明

| 权限 | 用途 |
|------|------|
| `BIND_ACCESSIBILITY_SERVICE` | 核心：保活与手势都依赖无障碍服务 |
| `FOREGROUND_SERVICE` | 保活前台服务 |
| `POST_NOTIFICATIONS` | 显示保活状态 |
| `RECEIVE_BOOT_COMPLETED` | 开机自动恢复 |
| `VIBRATE` | 手势触发反馈 |
| `QUERY_ALL_PACKAGES` | 枚举无障碍服务列表 |

**不联网、不收集数据、无第三方 SDK**（唯一的第三方依赖是 Shizuku API，用于可选的提权切换方式，不装 Shizuku 也能正常用）。

## 诊断

应用内可导出诊断日志（`files/diag.log`），记录每次保活修复、手势触发、服务切换的结果。

日志默认只保留异常与结构性事件；纯成功流水账会被过滤（见 `Diag.kt` 的 `NEVER_KEEP` 与 `shouldKeep`）。

## 已知限制

- **摇一摇 / 背面敲击的熄屏可用性取决于机型**：部分设备的加速度计是 Non-wakeup 型，深度睡眠时收不到样本。音量键和距离感应不受影响。
- **厂商私有传感器不做适配**：如 OPPO 的 `pocket`/`lay_detect` 等，换机型即失效，故不纳入。
